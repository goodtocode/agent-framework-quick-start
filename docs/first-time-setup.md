# First-Time Setup

For a fresh clone, run `Update-Branding.ps1 -NewCompany Contoso -NewProduct Assist -Apply`
after reviewing its dry run. Both brand values are required. The root entry point retains those
defaults and passes them explicitly to the shared initializer; installation never runs branding.
Without rebranding, the defaults are `Goodtocode` / `AgentStart`, including the local
database name and lowercase `agentstart` workflow/resource prefix.

Run PowerShell 7 from the clone root. Existing sign-in/workload tenants, a workload subscription,
an approved Azure OpenAI deployment/key, and Windows LocalDB for local development are prerequisites.
An empty subscription alone is not sufficient: the current workload IaC does not provision the
sign-in tenant or Azure OpenAI deployment, and CI tests require the AI endpoint and key.

```powershell
./Initialize-Installation.ps1 -Mode Cloud -Stage Prepare -Environment development -SqlAuthentication EntraOnly -InstallPrerequisites
# Publish reviewed source and workflows, then run agentstart-iac.yml with environment=development and runcd=true.
./Initialize-Installation.ps1 -Mode Cloud -Stage Complete -Environment development
# Run agentstart-app.yml with environment=development and runcd=true.
```

Prepare reconciles sign-in registrations and GitHub federation/environment/secrets. It needs a
user authorized to create or update app registrations, grant consent, and assign the deployment
identity its Azure role. It prompts privately for missing existing credentials and exits at the IaC checkpoint.
Complete verifies successful named deployment outputs, adds hosted redirects and provisions
Entra database users as the authorized signed-in SQL administrator. SQL-auth pipelines provision
database users automatically. No resource deletion, database reset or authentication conversion occurs.

For a new local clone, run `./Initialize-Installation.ps1 -Mode Local -Stage Prepare` separately.
Cloud Prepare is a one-time per-environment bootstrap, not a prerequisite for every clone; Complete
must be rerun after changes that require SQL access or hosted redirect reconciliation.

Use `-Mode Both` to combine preparation and `-Stage Check` for a non-mutating file/tool check.
Use `-SkipDatabase` when not using local SQL. `-InstallPrerequisites` installs missing CLI/.NET tools
through winget; LocalDB and tenant/subscription creation remain external prerequisites.

Pass `-SignInTenantId`, `-SignInInstanceUrl`, `-WorkloadTenantId`, `-SubscriptionId`, `-GitHubOwner`,
`-GitHubRepository`, and `-ResourceGroupName` to avoid non-secret prompts. Preserve the same
`-Environment` and `-Instance` for Prepare and Complete. Production requires corresponding IaC
parameter files and workflow planning to be enabled first; this script does not invent them.

GitHub federation defaults to one `github-agentstart` application shared across environments. Pass
`-GitHubPrincipalName` to reuse a differently named application; Prepare stores that name for
Complete. Existing matching issuer, subject, and audience credentials are reused, including
main and pull request subjects, and unrelated credentials are not deleted. Each environment
still needs its own GitHub environment and deployment permissions in its subscription.

Existing registrations/secrets are reused. On a new machine, privately enter missing existing
client secrets; automatic retrieval from Entra/GitHub is impossible. `-RotateSecrets` is explicit
and requires updating all consumers. State stays in local user-secrets per environment/instance;
user-secrets are not encrypted storage and must not be committed, printed or exported.

For Entra-only, select `-SqlAuthentication EntraOnly`, configure an existing workload SQL administrator
group, and resume as a group member. Prepare validates that the group exists in the workload tenant
and is security-enabled. Contributor alone is insufficient for SQL user provisioning. For `SqlAuth`, the script
prompts for the four administrator/migration secrets and uploads them securely. Runtime passwords
are generated by the provisioning pipeline, not extra setup secrets.

`-CreateRepository` explicitly creates a missing private repository without committing or pushing.
Publish reviewed source/workflows yourself before running IaC. Existing GitHub environment protections
are preserved. Advanced local-only options remain available in `.github/scripts/setup/Initialize-Development.ps1`; the old root entry points have been replaced.

## Azure SQL resource contract (Sequence 1 foundation)

The [workload template](.azure/templates/workload-digitalproduct.bicep) supports independently
created or referenced SQL servers through `sql.server.kind`: `EntraOnly` requires an existing
workload-tenant administrator group; `Existing` creates only the product database on an
owner-approved server. `SqlAuth` selects SQL authentication at creation with
`administratorLogin` and the separate secure `sqlAdministratorPassword` parameter.
Standalone parameters select Entra-only SQL and a dedicated API UAMI. LocalDB continues
to use Windows authentication independently.

Set `api.userAssignedIdentityName` for a dedicated workload-owned UAMI on a reviewed Entra
deployment. Outputs distinguish Azure RBAC object IDs from SQL/SqlClient client IDs.
After resource deployment, an authorized SQL administrator runs
[Set-AzureSqlManagedIdentityUsers.ps1](.azure/scripts/sql/Set-AzureSqlManagedIdentityUsers.ps1)
with distinct runtime and migration client IDs; it grants DML to runtime and DML/DDL to
migration without `db_owner` or Graph name lookup.

The hosted workflows read named deployment outputs and use the GitHub OIDC identity for
migrations. Configure `SQL_ENTRA_ADMIN_GROUP_OBJECT_ID` in IaC YAML `env` (or an environment
secret when YAML is empty) and the existing
OIDC tenant/subscription/client IDs, deploy IaC, provision contained users as the administrator,
then run app CD. Verify SQL-backed behavior, sign-in, least privilege and redeployment.
IaC fixes authentication at creation and never converts an existing server. The workflow checks
the existing mode and selects ordinary updates with `sqlCreateServer=false`, omitting creation-only
authentication properties while reconciling the Entra administrator of workload-owned servers and
continuing to manage tags, networking, firewall IPs and databases. This can replace the existing
administrator group with the configured group; review the IaC what-if before deployment.
Manual redeployments must pass that flag explicitly. Referenced servers must match their configured
`authentication` (default `EntraOnly`). Deployment locks prevent overlapping
mutations, not workflow ordering. No live installation is implied by local validation.

For `SqlAuth`, configure four environment secrets before the first IaC run: `SQL_ADMIN_USER`,
`SQL_ADMIN_PASSWORD`, `SQL_MIGRATION_USER`, and `SQL_MIGRATION_PASSWORD`. IaC and app CD
automatically provision restricted migration and runtime database users. The runtime password is
generated and reused from the API App Service connection string; no runtime secrets or manual SQL
resource changes are needed. The administrator is used only for provisioning, not migrations or runtime.
Product parameters and both workflows use instance `100`; mode changes require a replacement,
not a pipeline conversion or automatic deletion. Entra-only remains the default.

Choose the administrator group in the deployment owner's workload tenant; customer deployments
must not automatically grant publisher access. The current contract requires an administrator
group, not a no-human-access model. Routine operator access should use separate least-privilege
database grants. Cloud prototype resets must be separate, explicitly targeted destructive
operations; local EF resets must not implicitly reset Azure. Rewritten migration baselines
require an approved disposable cloud database rebuild and contained-user provisioning.

AI authentication and web app secrets remain separate follow-up changes, not extra requirements
for a local clone. AI test credentials are environment inputs, not baked into published settings.

## Quick-Start: Full Setup (new or first-time environment)
```powershell
# Clone repository
git clone https://github.com/goodtocode/agent-framework-quick-start.git

# Enter repository root
cd agent-framework-quick-start

# Install .NET SDK 10
winget install Microsoft.DotNet.SDK.10 --silent

# Trust local ASP.NET Core HTTPS development certificate (first-time machine setup)
dotnet dev-certs https --trust

# Install EF CLI
dotnet tool install --global dotnet-ef

# Fill in the values below, then run the local install script. It creates the Entra app registrations and grants consent,
# sets the user-secrets for Presentation.Api, Presentation.Web and Tests.Integration, and applies the EF migrations to
# your local SQL Server (LocalDB). No copy/paste between steps. Omit AzureOpenAIApiKey to be prompted without echo.
$install = @{
    EntraInstanceUrl    = "https://<your-tenant-name>.ciamlogin.com"
    EntraTenantId       = "<entra-tenant-id>"
    AzureOpenAIEndpoint = "https://<resource>.openai.azure.com/openai/v1"
    AzureOpenAIApiKey   = "<azure-openai-api-key>"
}
./.github/scripts/setup/Initialize-Development.ps1 @install

# Run integration tests
cd src/Tests.Integration
dotnet test

# Return to src and run API
cd ../
dotnet run --project Presentation.Api/Presentation.Api.csproj

# Run Web app in a second terminal
dotnet run --project Presentation.Web/Presentation.Web.csproj
```

## What the local install script does
`.github/scripts/setup/Initialize-Development.ps1` sets up localhost only. It never touches GitHub, Azure Pipelines or Azure resources; see "Setting up GitHub Actions to Deploy to Azure" below for CI/CD.
- **Entra:** registration names use the selected product prefix, for example `agentstart-api-dev-100` and `agentstart-web-dev-100` for the template root entry point. The script grants admin consent and writes the Entra user-secrets. The Web redirect and logout URIs are read from the HTTPS URL in `Presentation.Web/Properties/launchSettings.json`, so they always match your local port.
- **User-secrets:** `AzureOpenAI:Endpoint` and `AzureOpenAI:ApiKey` for `Presentation.Api` and `Tests.Integration`, and an empty `ApplicationInsights:ConnectionString` for `Presentation.Api` and `Presentation.Web`.
- **Database:** installs `dotnet-ef` if missing and applies the EF migrations to LocalDB (`Initial Catalog=AgentStart`). Use `-DatabaseConnectionString` for another SQL Server, or `-SkipDatabase` to skip it.
- **Existing Entra registrations:** add `-SkipEntra` to skip the first step, or use the re-setup block below.

**Application Insights:** the apps start without a connection string, with no Azure telemetry (a warning is logged). The connection string only exists after the infrastructure PR deploys. Then set it for both apps from the repo root:
```powershell
dotnet user-secrets set "ApplicationInsights:ConnectionString" "<connection-string>" --project .\src\Presentation.Api\Presentation.Api.csproj
dotnet user-secrets set "ApplicationInsights:ConnectionString" "<connection-string>" --project .\src\Presentation.Web\Presentation.Web.csproj
```
In Azure, the deployment sets the connection string for you.

**Azure OpenAI deployment names:** all committed environments use `chat-fast`, `tool-standard`, `tool-reasoning`, and `embedding-standard`, matching the shared `platform-azure` Foundry deployments. To use different purpose-compatible deployments, update `src/Presentation.Api/appsettings.*.json`, or pass `-ChatDeploymentName`, `-ToolDeploymentName`, `-ToolReasoningDeploymentName`, and `-EmbeddingDeploymentName` to `.github/scripts/setup/Initialize-Development.ps1` for local user-secret overrides only. Deployment names are not secrets.

## Quick-Start: Re-Setup for Existing Entra (no Entra setup scripts)
```powershell
# Enter repository root
cd <path-to-repo-root>

# Set API secrets (run from the repository root)
dotnet user-secrets set "EntraExternalId:Instance" "https://<your-tenant-name>.ciamlogin.com" --project .\src\Presentation.Api\Presentation.Api.csproj
dotnet user-secrets set "EntraExternalId:TenantId" "<entra-tenant-id>" --project .\src\Presentation.Api\Presentation.Api.csproj
dotnet user-secrets set "EntraExternalId:ClientId" "<api-client-id>" --project .\src\Presentation.Api\Presentation.Api.csproj
dotnet user-secrets set "EntraExternalId:ValidateAuthority" "true" --project .\src\Presentation.Api\Presentation.Api.csproj
dotnet user-secrets set "ApplicationInsights:ConnectionString" "" --project .\src\Presentation.Api\Presentation.Api.csproj
dotnet user-secrets set "AzureOpenAI:Endpoint" "https://<resource>.openai.azure.com/openai/v1" --project .\src\Presentation.Api\Presentation.Api.csproj
dotnet user-secrets set "AzureOpenAI:ApiKey" "<azure-openai-api-key>" --project .\src\Presentation.Api\Presentation.Api.csproj

# Set Web secrets
dotnet user-secrets set "BackendApi:ClientId" "<api-client-id>" --project .\src\Presentation.Web\Presentation.Web.csproj
dotnet user-secrets set "EntraExternalId:Instance" "https://<your-tenant-name>.ciamlogin.com" --project .\src\Presentation.Web\Presentation.Web.csproj
dotnet user-secrets set "EntraExternalId:TenantId" "<entra-tenant-id>" --project .\src\Presentation.Web\Presentation.Web.csproj
dotnet user-secrets set "EntraExternalId:ClientId" "<web-client-id>" --project .\src\Presentation.Web\Presentation.Web.csproj
dotnet user-secrets set "EntraExternalId:ClientSecret" "<web-client-secret>" --project .\src\Presentation.Web\Presentation.Web.csproj
dotnet user-secrets set "EntraExternalId:ValidateAuthority" "true" --project .\src\Presentation.Web\Presentation.Web.csproj
dotnet user-secrets set "ApplicationInsights:ConnectionString" "" --project .\src\Presentation.Web\Presentation.Web.csproj

# Set integration test Azure OpenAI secrets
dotnet user-secrets set "AzureOpenAI:Endpoint" "https://<resource>.openai.azure.com/openai/v1" --project .\src\Tests.Integration\Tests.Integration.csproj
dotnet user-secrets set "AzureOpenAI:ApiKey" "<azure-openai-api-key>" --project .\src\Tests.Integration\Tests.Integration.csproj

# Optional: EntraExternalId:PasswordResetUrl (Web), and AzureOpenAI:ChatDeploymentName / AzureOpenAI:EmbeddingDeploymentName
# (Api and Tests.Integration) only when you need to override the appsettings values.

# Create or update SQL schema
dotnet ef database update --project .\src\Infrastructure.SqlServer\Infrastructure.SqlServer.csproj --startup-project .\src\Presentation.Api\Presentation.Api.csproj --context ApplicationDbContext --connection "Data Source=(localdb)\MSSQLLocalDB;Initial Catalog=AgentStart;Min Pool Size=3;MultipleActiveResultSets=True;Trusted_Connection=Yes;TrustServerCertificate=True;MultipleActiveResultSets=False;Encrypt=True;TrustServerCertificate=False;Connection Timeout=30"
```

For detailed alternatives and troubleshooting, see the Authentication section below.
